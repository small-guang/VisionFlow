# 人脸与人型质量及入库规则

本文定义人脸、人型的质量门槛、识别资格和入库条件。`0级` 丢弃，`1级` 只识别已有身份，`2级` 具备建库质量，仍须通过身份与样本更新规则。

每张关键帧先处理人脸，再处理人型。运行顺序和并发见[架构文档](代码架构与处理流程.md)，ReID 候选解析见[人型 ReID 识别完整流程](人型ReID识别完整流程.md)。

每帧人脸/人物允许有界提前准备：对应 `FRAME_CONCURRENCY=N` 限制同时准备数，`PREPARE_LOOKAHEAD=M` 限制额外前瞻量，准备中、等待提交和正在提交合计最多 N+M 项。准备完成可继续准备后续目标，检测记录、身份决策和 pending 登记仍按原检测顺序提交；人型仍等待该图人脸处理完成。M=0 保持原 N 项窗口，同帧串行需 N=1 且 M=0。后序准备失败不会打断前序提交，到该失败项时才停止并清理后序；取消则清理全部未完成任务。

## 一、人脸质量与入库

### 1. 人脸处理顺序

检测与扩展裁剪、编码后，并行执行“扩展 crop 上传”和“关键点 → 前置判断 → 质量评分与分级”。两条分支汇合后，只有非 0 级且 crop 上传成功才进入特征提取 → 身份匹配 → 按条件入库。前置判断失败或最终 0 级时不提取特征，但仍等待已发起的上传步骤结束；上传失败仍禁止该独立人脸进入特征提取。并行只改变准备阶段的等待关系，检测记录、身份决策与 pending 登记仍按原检测顺序提交。

### 2. 人脸前置判断规则

以下阈值以 `utils/quality/face_quality.py` 当前实现为准。只要任一前置条件不满足，即判定为不通过，记为 `0` 分、`0级`，后续不再进入质量评分、识别或入库流程。

人脸框与裁剪区域：

- 人脸框无效，判定不通过。
- 扩展裁剪区域无效，判定不通过。
- 原始人脸裁剪图为空，判定不通过。
- 扩展人脸裁剪图为空，判定不通过。

关键点有效性：

- 关键点提取失败，判定不通过。
- 关键点为空，判定不通过。
- 关键点数量不足，判定不通过。
- 关键点坐标格式异常，判定不通过。

几何判断：

- 人脸宽度小于等于 `20px`，判定不通过。
- 所有关键点必须落在人脸框范围内，任意关键点超出人脸框则判定不通过。
- 鼻尖横向位置必须位于左右眼之间，否则判定不通过。
- 鼻尖纵向位置必须位于眼睛和嘴角之间，否则判定不通过。
- 独立人脸质量前置判断：姿态计算有效时，`pitch`、`yaw`、`roll` 任一角绝对值大于 `65°`，判定不通过；恰好 `65°` 不因本项拒绝。朝向标签仍以 `yaw` 的 `20°` 为分界，见下文。
- 关键点两两距离标准差大于平均距离的 `65%`，判定为关键点几何波动过大，不通过。

模糊度检测：

- 使用 Laplacian 方差判断图像清晰度。
- Laplacian 方差 `<12` 时判定不通过，恰好 `12` 通过本项。

人型 crop 内人脸绑定使用相同的宽度、姿态、几何波动和清晰度阈值，但姿态按扩展人脸 crop 的局部坐标计算，独立人脸按整图坐标计算。特征提取后的原始 L2 norm 门槛不同：独立人脸必须 `>0.3`，人型内人脸绑定必须 `>0.2`，等于门槛均拒绝；通过后再用归一化向量检索。

### 人脸朝向输出

人脸检测、人脸识别、人型检测和人型识别记录都会输出 `faceOrientation`，允许值仅为 `front`、`side`、`no_face`、`unknown`。朝向分类仅使用 `yaw`：`abs(yaw) < 20°` 为 `front`，`abs(yaw) >= 20°` 为 `side`，因此纯侧脸和恰好 `20°` 的边界均为 `side`。`pitch` 与 `roll` 仅用于诊断，不参与朝向分类，也不作为 Kafka 输出字段。

独立人脸记录正常流程不使用 `no_face`；人脸检测、关键点或姿态失败时输出 `unknown`。人型在人物裁剪、实例 mask 与检测响应有效后，检测列表为空，或至少有一个有效 bbox 但所有候选未通过 mask/Pose 归属门控（包括可用 Pose 头部锚点与候选全不匹配）时输出 `no_face`，而非 `unknown`。检测响应非 list、非空列表没有有效 bbox，以及裁剪、mask、关键点或姿态计算异常同样输出 `unknown`。`faceOrientation` 不参与人脸质量、ID 分配或入库判定。

### 3. 人脸质量分级规则

前置判断通过后，调用 `face_qa_ensemble` v2 获取质量分。VisionFlow 将扩展后的人脸图和该图局部坐标系下的 5 点关键点一并发送给 Triton；Triton 按原 ModelScope 模型的标准模板做 112×112 相似变换对齐，再将模型 10 个原始序数输出取均值并乘以 `10`。业务质量分为 `0` 到 `10` 的连续浮点数。

| 质量分数 | 等级 | 处理策略 |
| --- | --- | --- |
| 前置判断不通过 | `0级` | 记为 `0` 分，丢弃 |
| `0 <= 分数 < 2` | `0级` | 丢弃 |
| `2 <= 分数 < 4.5` | `1级` | 仅用于识别，不入库 |
| `4.5 <= 分数 <= 10` | `2级` | 具备建库质量，仍须通过身份入库规则 |

分数边界说明：

- `2` 分进入 `1级`，可用于识别。
- `config/algorithm.toml` 中的 `face.quality.enroll_min_score` 当前为 `4.5`，达到该值进入 `2级`，可用于建库。
- 前置判断不通过时，不再依赖质量模型输出，统一按 `0` 分处理。

上述分级只用于独立人脸。人型 crop 内人脸绑定另用 `person_face.binding.quality_min_score=1.5`，只复用已有 Face ID，不输出 `faceQualityLevel`，也不创建人脸 ID 或向量；人型自身的质量分级仍为 `5/7`。

### 4. 人脸各等级处理逻辑

- `0级`：保留检测结果，不提取特征、查询或入库。
- `1级`：提取特征并匹配已有 Face ID，未命中保持未分配。
- `2级`：正常未命中时可创建 Face ID；命中已有 ID 时，只有达到单样本确认线才提交样本更新。灰区确认只复用 ID。

检索异常和灰区证据不足均返回 `face_id=0/faceStatus=0`，禁止创建或入库。正常未命中产生的新生识别记录等待首次人脸向量持久化确认，失败时随向量重试。详细判定见下文“身份匹配与入库”。

### 5. 人脸图库容量与质量更新

- 同一个 `faceId` 跨设备最多保留 `FACE_MAX_VECTORS_PER_ID` 条向量，默认 `20`，配置范围 `1–1000`。
- `qualityScore` 必须是 `[face.quality.enroll_min_score,10]`（当前 `[4.5,10]`）内的有限分数，并通过身份入库规则。容量未满时加入合格样本；容量已满时比较新样本与库内“质量最低、同分时采集时间最旧”的样本。
- 质量更高则替换；质量相同时，仅采集时间 `timestamp` 更新才替换；质量更低或质量和时间均相同则跳过。消息到达时间不参与排序。
- 向量表保存 `qualityScore`（DOUBLE）和 `sampleId`。每次观察的 `sampleId` 在重试期间保持不变，服务端已写入但回执丢失时，通过强一致查询确认已有样本，避免重复占用名额。
- `id` 为手动生成的整数，表示固定保留位置；替换使用同一主键 `upsert`，同时更新向量、质量、采集时间和裁剪信息。`faceId` 为分区键，跨设备更新仍属于同一身份的图库。
- 被质量策略跳过的样本退出 pending，不发送向量信息记录；识别事件继续正常发送。新生事件需要确认该身份至少有一条已持久化向量，即使最初那条 pending 样本已被同一身份的更优样本取代。
- 下调容量后，身份下次写入时先清理超额的低质量/旧样本。进程内用锁串行执行比较与更新；多个独立写入进程需要共享协调，才能保证全局质量单调更新。
- 启动时校验集合结构，不自动迁移已有数据。

## 二、人型质量与入库

### 1. 人型裁剪与处理

人物分割与 Pose 绑定后，对每个人物执行结构质量、裁剪、图像预检、人脸绑定和特征提取，再按原检测顺序提交检测与身份结果。并发窗口和全局名额见 [配置说明](configuration.md#并发与组批)。

所有人物先生成检测框四边 `5%` 的自然窗口。`panoKeyframeUrl` 来源、SN 含 `EPS`（忽略大小写）或位于 `PERSON_UPRIGHT_DEVICE_SNS` 名单的设备启用转正；同一消息的主图不会仅因携带全景图而启用。手动名单清空不影响自动启用规则。

转正使用可靠 COCO-17 同侧肩→髋方向，成功后依据 mask/Pose 支撑区安全紧裁剪；未启用、Pose 不足、角度死区、方向冲突或旋转失败时，保留未旋转自然窗口。crop 允许可变宽高比，缺少真实图像内容的区域使用 BGR `(104,116,124)`，mask 补零；不执行鱼眼畸变矫正。

图像、目标/外来人物 mask 和 crop Pose 共用原图到最终 crop 的仿射变换，图像用线性插值，mask 用最近邻插值。整图 `peopleRect/personRect/personKeypoint` 保留原坐标。图像预检、OSS、SBS、TBPS/CLIP 和人脸绑定使用同一最终 crop，各模型在自身预处理中缩放到固定输入尺寸。

结构门控已判 0 级时跳过图像预检。所有有效非空 crop 都尝试上传，包括最终丢弃样本；上传失败不阻断符合条件的人型特征提取与 SBS enrollment，裁剪地址为空。0 级或编码失败时不提取人体向量，只提交检测记录；有效 crop 与 mask 可用于脸部朝向分析。

裁剪、质量合并与编码完成后，非 0 级且编码成功的样本并行执行两条分支：一条先完成上传，再执行人物 crop 内人脸匹配；另一条提取 SBS，以及 2 级样本的 TBPS/CLIP 特征。人体特征推理无需等待上传，两条分支均完成后才进入原有按序提交。0 级或空编码样本不启动人体特征分支，仍完成上传步骤（空编码不发送图片），再以 `enable_recognition=False` 执行脸部朝向分析，Face ID 保持 `0`。

人脸和人型的并行分支均由当前目标任务持有。未捕获异常或取消会取消其余分支并等待协程清理完成，重复取消不会提前结束清理；已完成的上传与已提交结果不回滚。已开始的存储 SDK 线程可能继续完成网络调用，由原执行池在真实线程结束后归还容量，不能把协程取消视为上传已停止。

### 人型 crop 内人脸绑定

人型内检测到人脸时，候选人脸框中心必须位于当前人物 mask 内，且候选人脸框内目标实例 mask 的像素覆盖率至少为 `0.50`。若有可用 COCO-17 鼻、眼、耳头部点形成的 Pose 头部锚点，锚点必须落入候选人脸框四边各扩 `25%`（横向按框宽、纵向按框高）的范围；没有可用锚点（未提供、形状无效，或鼻/眼/耳均不可用）时归属选择仅按 mask 门控回退。人物裁剪、实例 mask 与检测响应有效后，检测列表为空，或至少有一个有效 bbox 但所有候选未通过 mask/Pose 归属门控时输出 `faceOrientation=no_face`、返回 `face_id=0`，并跳过人脸关键点、质量评分、特征提取和人脸向量库检索，不按最高检测置信度兜底。检测响应非 list、非空列表没有有效 bbox，以及 crop、mask、关键点或姿态计算异常才输出 `faceOrientation=unknown`。归属选择不决定是否执行人脸识别，后者仍受既有 `enable_recognition` 和 `0级` 规则控制。归属后质量模型分数必须 `>= 1.5` 才继续特征提取和搜索，低于 `1.5` 时返回 `face_id=0`，恰好 `1.5` 允许继续。独立人脸流程按 `2.0` 起划为 `1级`，人型内绑定使用单独的 `1.5` 门槛，人型记录不分配 `faceQualityLevel`；它独立于下述 `0.43/0.5` 灰区双样本匹配规则。这些人型 crop 门控适用于本地流程和部分复用；可靠的直接身份复用信任已确认的整图非零 ID，不重新执行质量 `>=1.5` 或人脸合并搜索。

### 同帧整图人脸复用状态机

整图人脸流程先为本张图片返回 `FrameFaceObservation[]`；人型流程只接收同一张原图的列表。主图与 `panoKeyframeUrl` 分别处理、分别绑定和统计，禁止跨图、跨消息或跨帧缓存。默认 `PERSON_FACE_REUSE_MODE=on`，复用固定覆盖到特征阶段；可在异常时设为 `off`，让每个人物在最终 crop 内独立执行人脸检测、关键点、质量、特征和搜索。

每个人物按以下规则选择共享或完整本地流程：

1. `off`：不读取整图观察，直接本地流程。
2. `on`：人物最终 crop 若已成功执行转正旋转，则以 `person_rotated` 为原因直接进入完整本地流程，不尝试采用整图身份、特征或朝向；未旋转人物才用当前实例 mask、候选框中心/覆盖率，以及可用 Pose 头部锚点进行归属。没有候选为 `no_owned_face` 回退；一个整图脸被多个非重复人物声明为 `ambiguous_non_duplicate_people`，这些人物都回退。只有 bbox IoU 与 mask IoU 同时满足重复检测条件的同一人物重复实例可共享该观察。
3. 对唯一 `bound` 观察验证来源框、阶段和字段。任一 `completed_stage` 已承诺的字段必须结构有效：所有阶段需要有效来源框，`LANDMARKS` 或更高还需要有限精确 5×2 关键点，`QUALITY` 或更高还需要有限质量分，`FEATURE` 或更高还需要有限的一维单位向量和非负原始范数。识别关闭时，结构完整的 `LANDMARKS` 或更高阶段会把整图关键点转换到该脸的扩展 crop 坐标，再按既有人型规则重新计算 `front/side`，ID 固定 `0`；不直接复制整图朝向标签，坐标转换或姿态计算不能得到已知朝向时回退。直接身份复用同样只复用 ID，输出给人型记录的朝向仍按该规则重算。
4. 识别开启时，只有结构完整的 `IDENTITY` 链、受支持的非零标量 ID 和空字符串失败元数据才能直接复用身份。没有可靠非零 ID 时，可从结构有效的 `DETECTION`、`LANDMARKS`、`QUALITY`、`FEATURE` 或 `IDENTITY` 观察继续部分复用；任何已承诺字段格式错误都完整本地回退，而不会只丢弃该字段后继续共享。
5. 部分复用固定覆盖到特征阶段：结构有效的 `FEATURE` 或更高阶段复用特征和原始范数，较早阶段重新推理缺失的关键点、质量和特征。部分复用仍执行人型 crop 质量 `>=1.5`、人脸灰区双样本门控，并在身份锁内复核候选、合并最新 pending；远程候选可以按下文规则锁外预取并最多刷新一次，仍不可用时完整锁内重查。可靠的直接身份复用不重跑这些门控或搜索。任一共享搜索结果为 `0`、共享调用异常、字段不完整或格式错误，均回退。只有非零共享结果才能替代本地识别结果。

`feature` 复用前，共享归一化人脸特征必须是有限一维向量，且 L2 范数与 `1.0` 的绝对误差不超过 `PERSON_FACE_NORMALIZED_EMBEDDING_NORM_TOLERANCE=1e-4`；原始范数必须有限且非负。任一条件不满足时，当前人物回退本地人脸特征提取。

人脸共享只复用整图观察，身份分配与入库由各自流程执行。可靠的直接身份复用信任已确认整图 ID；部分复用与本地回退适用人型 crop 的质量和相似度门槛。

本地回退使用实际最终 crop 的坐标系；成功转正时 `on` 也强制本地处理，整图框和关键点不回写。帧级复用统计见[架构文档](代码架构与处理流程.md#63-crop-内人脸与同图复用)。

### 2. 人型前置判断规则

以下情况直接判定为不通过，记为 `0` 分、`0级`：

- 人型框无效。
- 人型框宽度或高度小于等于 `0`。
- 人型裁剪图为空。
- 完整 Pose 流程中 mask 缺失、形状无效或没有前景，导致无法完成 Mask–Pose 绑定。
- `maskScore < 5`，等价于 `maskPixelCount < 6000`。
- `confidence` 为空、NaN、无穷大或小于等于 `0`。
- bbox 过小、确认的严重原图内容截断、与其他人型严重重叠，或 mask/bbox 占比过低。

VisionFlow 当前不额外设置 `confidence >= 0.5` 的 person 检测门槛；正常正值继续进入 Mask/Pose/Crop 质量门控，只有空值、NaN、无穷大或小于等于 `0` 的异常值会被保护性丢弃。

### 3. 人型像素分折算规则

人型基础 mask 分按 mask 像素数量线性折算：

```text
maskScore = min(maskPixelCount / 12000 * 10, 10)
```

说明：

- `maskPixelCount` 表示人型分割 mask 的有效像素数量。
- `12000` 为满分像素值。
- `maskPixelCount >= 12000` 时，基础 mask 分按 `10` 分处理。
- `maskPixelCount < 12000` 时，按比例折算为 `0` 到 `10` 分。
- 最终质量等级还会受 Mask/Crop 门控限制，例如低 mask/bbox 占比、多连通域、确认的真实内容截断、bbox 过小、bbox 比例异常和多人重叠。

### 4. 人型 Pose 门控规则

VisionFlow 并发调用分割和 `yolo26m_pose_ensemble`，以人物实例 mask 为归属锚点。候选必须同时满足 bbox IoU `>=0.3`、可见 Pose 关键点与 mask 一致率 `>=0.60`；匹配分为 `0.70 * mask一致率 + 0.30 * bbox IoU`，再按匹配分执行确定性一对一绑定。关键点置信度 `>=0.5`、坐标有限且位于原图内时计为可见。没有可靠候选时以 `pose_not_matched` 严格丢弃，不进入 ReID。

```text
poseScore = 5 * visibleCount / 17
          + 2 * visibleShoulderHipCount / 4
          + 1 * visibleKneeAnkleCount / 4
          + 1 * completeShoulderHipChainCount / 2
          + 1 * min(verticalSpanRatio / 0.65, 1)

personQualityScore = 0.55 * poseScore + 0.30 * maskScore + 0.15 * cropScore
```

Pose 请求失败、无匹配结果、关键点格式无效、可见点少于 `6`、肩髋四点可见数不超过 `1` 时硬拒绝。没有完整肩髋链路、没有髋膝链路、半身/局部人体、纵向跨度比例 `<0.35`、落入分割框比例 `<0.70`，或有效 mask 存在时落入 mask 比例 `<0.60`，通常最高为 `1级`。唯一例外是 `half_body_upper`：可见关键点 `>=11`、两肩两髋全部可见、两侧 shoulder→hip 链均完整，且除半身/下肢缺失、靠近边缘和 mask 触达检测框诊断外没有其他降级或拒绝条件时，可免除半身与下肢缺失上限并达到 `2级`。

### 5. 人型 Mask/Crop 门控规则

人型最终等级由基础 mask 分和门控规则共同决定。门控分为两类：

- 硬拒绝：直接 `0级`，不提取 SBS R50-IBN/CLIP，不识别，不入库。
- 建库拦截：最高只能 `1级`，可以通过 SBS R50-IBN 识别已有 `reid`，但不生成新 `reid`，不写入 `alogSBS` 或 `alogTBPS`。

Mask 门控：

| 条件 | 处理 |
| --- | --- |
| `maskArea / bboxArea < 0.12` | 硬拒绝 |
| `0.12 <= maskArea / bboxArea < 0.25` | 最高 `1级` |
| mask 最大连通域占比 `< 0.55` | 硬拒绝 |
| mask 存在多个大连通区域 | 最高 `1级` |
| mask 触达检测 bbox 边 | 只记录普通/严重诊断，不降级、不丢弃、不设置 `isTruncated` |
| 单独调用 Mask helper 时 mask 缺失或尺寸异常 | 记录原因并退回基础 mask 分；完整流水线在 Mask–Pose 绑定阶段拒绝此类输入 |

Crop/Bbox 门控：

| 条件 | 处理 |
| --- | --- |
| `confidence` 为空、NaN、无穷大或 `<= 0` | 硬拒绝 |
| bbox 无效、`w < 24`、`h < 48` 或 `bboxArea / imageArea < 0.002` | 硬拒绝 |
| `bboxArea / imageArea > 0.85` | 最高 `1级` |
| `h / w < 0.8` 或 `h / w > 5.0` | 最高 `1级` |
| bbox 靠近任意数量的图像边 | 只记录 `bbox_near_image_edge` 和 `nearImageEdgeCount`，不单独降级 |
| 已确认截断且 `bboxOverflowRatio >0.20`、`<=0.50` | 最高 `1级` |
| 已确认截断且 `bboxOverflowRatio >0.50` | 硬拒绝 |
| 确认截断边数 `>=3` | 硬拒绝 |
| 与其他 person bbox 重叠比例 `> 0.40` | 硬拒绝 |
| 与其他 person bbox 重叠比例 `> 0.15` | 最高 `1级` |

最终 crop 中有效外来人物 mask 的污染门槛：

| 条件 | 处理 |
| --- | --- |
| 总占比 `>=30%` 或目标中央 70% 核心区占比 `>=20%` | 硬拒绝 |
| 总占比 `>=10%` 或核心区占比 `>=5%`，且未达到硬拒绝线 | 最高 `1级` |
| 低于上述门槛 | 只记录诊断 |

其他人物 mask 无效时的 bbox 回退只作诊断，不参与 crop 等级门控。

Crop 几何诊断统一限制在 `[0,1]`。`paddingRatio` 表示最终 crop 中无法从旋转前 `5%` 自然窗口取得真实像素、由均值色提供的像素占比：在原图范围内的自然窗口上建立 source-validity mask，使用与图像相同的仿射变换和最终 crop 坐标（成功转正时包含紧裁剪平移），以最近邻方式投影后逐像素计算 `1 - validPixelCount / finalCropPixelCount`。`letterboxPaddingRatio` 为兼容字段，检测记录和识别记录固定输出 `0.0`。`sourceOverflowRatio=(naturalWindowArea-inFrameNaturalWindowArea)/naturalWindowArea`，只统计旋转前 `5%` 自然窗口落在原图外的面积比例。`bboxOverflowRatio=1-clippedRawBBoxArea/rawBBoxArea`。转正角度和回退原因写入诊断信息。前三项比例均不参与等级门控；`bboxOverflowRatio` 只在人体截断已经确认后参与门控。

原图 mask 触边使用 `max(1px, round(原图短边×0.002))` 的边缘带；对应方向前景像素达到 `max(3, round(maskArea×0.002))` 才算有效证据。确认方向必须同时具备 bbox 与原图 mask 证据：raw bbox 确实越出该方向时直接确认；否则顶部还要求头部点全部缺失，底部还要求没有完整肩→髋→膝→踝链，左右不接受仅贴边确认。恰好 `bboxOverflowRatio=0.20` 不降级，恰好 `0.50` 不丢弃。

### 6. 人型图像预检

图像预检只对通过结构门控的 `1级/2级` 候选执行。预检把最终可变宽高比 crop 直接用 Bicubic 缩放到 `224x224`，mask 使用最近邻缩放；这只是预检自身的固定输入预处理，不改变外部共享 crop。SBS 和 TBPS/CLIP 同样在各自 Triton 模型预处理中直接缩放到固定输入尺寸。清晰度优先在腐蚀边缘保护带后的 mask 前景上计算，曝光和对比度在完整 mask 前景上计算。有效前景不足 `256` 像素时退回未腐蚀 mask 前景。独立调用图像预检 helper 时仍保留无 mask 的整图防御处理，但生产主流程要求有效 mask 完成 Mask–Pose 绑定，否则直接以 `pose_not_matched` 丢弃。

| 指标 | 硬拒绝，直接 `0级` | 建库拦截，最高 `1级` |
| --- | --- | --- |
| 前景 Laplacian 方差 | `< 10` | `10 <= value < 20` |
| 欠曝 | `gray<=5` 占比 `>=0.80`，或 `P95<=20` | `gray<=20` 占比 `>=0.70`，或 `P90<=40` |
| 过曝 | `gray>=250` 占比 `>=0.80`，或 `P5>=245` | `gray>=235` 占比 `>=0.70`，或 `P10>=220` |
| 对比度 `P95-P5` | `< 8` | `8 <= value < 20` |

多个条件可以同时命中，`qualityReasons` 会保留全部原因。任一硬拒绝条件优先得到 `0级`；没有硬拒绝但命中任一建库拦截条件时，`cropScore` 最高为 `6.99`。所有指标写入调试日志，命中门控时实际值和阈值还会写入人型检测记录 `info`。

### 7. 人型质量等级

| 联合质量分 | 等级 | 处理策略 |
| --- | --- | --- |
| 硬拒绝命中或 `<5` | `0级` | 丢弃 |
| `5 <= score < 7` | `1级` | 仅用于识别，不入库 |
| `score >= 7` 且未命中建库拦截 | `2级` | 具备建库质量；SBS 还需当前非零 observedFaceId，TBPS 只需有效 CLIP |

分数边界说明：

- maskScore `<5` 仍为硬拒绝；`5 <= maskScore < 7` 最高为 `1级`。
- `poseScore`、`maskScore`、`cropScore` 均为 `0-10` 分，最终按 `0.55/0.30/0.15` 权重合成。
- 命中任一门控降级或拒绝条件时，最终等级可能低于联合分对应等级。

### 人型躯干朝向输出

人型检测和人型识别记录始终输出字符串 `personOrientation`，允许值仅为 `front`、`side`、`back`、`unknown`；人脸记录和向量记录不输出该字段。它表示躯干/身体方向，独立于 `faceOrientation`，所以身体 `front` 而脸部 `side` 是合法组合；`faceOrientation` 的取值为 `front`、`side`、`no_face`、`unknown`。

分类使用 COCO-17 Pose。可靠的 shoulder→hip 链按其端点置信度的较小值加权合成向下轴 `down`，建立 `local_right=(down.y,-down.x)`；`torso_scale` 是可用 shoulder→hip 链长度按同一链权重的置信度加权平均。对每个可用左右肩/髋水平对（`left_point`、`right_point`），其权重为两端点置信度的较小值，并计算精确的 `signed_span_ratio = dot(left_point - right_point, local_right) / torso_scale`；两对的 `signed_span_ratio` 再按各自权重加权平均为最终 `score`（仅一对可用时直接使用该对）。最终边界为：`abs(score) <= 0.25`（包括恰好 `0.25`）为 `side`，`score > 0.25` 为 `front`，`score < -0.25` 为 `back`。

单个 Pose 点的坐标/置信度非有限、置信度低于可见阈值或落在图像外时，该点会被排除，不会单独令结果为 `unknown`。只要剩余点能形成至少一条可靠 shoulder→hip 躯干轴和一个完整的左右肩或左右髋水平对即可分类；仅剩一对时直接使用该对。Pose 形状或图像尺寸无效，剩余证据无法形成可靠躯干轴或完整水平对，肩髋轴/水平对发生冲突或非有限计算、左右肩髋的强证据符号冲突，以及未预期的内部错误（包括 `internal_error`）时严格收敛为 `unknown`。每个 observation 只分类一次，检测记录和识别记录复用同一个结果；该字段不影响人型质量等级、upright crop、ReID、特征提取、Milvus 检索或 enrollment。

### 8. 诊断字段

检测与识别记录输出最终质量分/等级、Pose/Mask/Crop 分数、完整度、截断和污染比例，以及 `qualityReasons`。检测记录还输出原图坐标下的 COCO-17 `personKeypoint`；识别记录使用 Pose 摘要。

公开字段和 reason code 的类型、取值及示例统一见 [Kafka Topic 契约](kafka_topic.md)。

内部 crop 几何诊断还保留 `content_xyxy` 和 `padding`，仅供内部使用，不作为 Kafka 字段：`content_xyxy=[x1,y1,x2,y2)` 是最终 crop 中有效 source 内容的轴对齐包围框；`padding=(left,top,right,bottom)` 是该包围框到最终 crop 四边的连续合成边界宽度。旋转角区等位于包围框内部的非 source 像素不属于四边连续边界，由逐像素的 `paddingRatio` 表达。

## 三、身份匹配与入库

### 1. 人脸身份确认

人脸完整查询先取得 pending 快照，再以 `Strong` 检索 Milvus，避免样本刷盘时从两个来源同时漏掉。合并后按最高单条相似度选取候选 Face ID；同分保留来源顺序（Milvus 优先）。返回的 `score` 和 `vectorHitFaceId` 对应该条最高命中。

默认 `FACE_SEARCH_PREFETCH_ENABLED=true` 时，可以先在短身份锁内固定本实例图库/pending 移除版本，再释放锁查询远程候选。轮到解析时持身份锁读取最新 pending，并在读取前后复核版本；只有版本稳定且没有真实写线程活动才复用候选。没有有效候选时，若当前可取得稳定版本且尚未刷新，则释放锁额外查询一次，再重新持锁复核。当前仍有真实写线程活动、能力缺失或一次刷新后仍不可用时，使用上述完整锁内查询；不等待 writer 空闲或继续重试。身份决策、记录构造至 pending 登记保持同一锁，业务异常不触发候选刷新，取消直接传播。

初次预取或刷新异常不作为“正常未命中”参与建库，最终完整查询失败仍禁止新建身份。关闭开关同时禁用初次预取和刷新，不改变身份、质量和持久化规则；SBS 身份流程不使用这项 Face 刷新机制。

图库版本覆盖真实同步写线程的进入、退出及异常；取消异步等待者不代表真实写线程结束。pending 新增由提交时的最新读取覆盖，真实移除才更新版本。版本只适用于当前实例，不能提供跨进程事务；候选只在本次请求内使用，不形成跨帧身份缓存。人物内部 Face 复用/回退共用该查询逻辑，但这段工作仍属于人物准备阶段。

| 最高相似度 / 结果 | 身份判定 | 样本处理 |
| --- | --- | --- |
| `>=0.5` | 单样本确认已有 Face ID | 2 级且通过图库更新策略时可入库 |
| `[0.43,0.5)`，同 ID 有两条独立样本各 `>=0.43` | 确认已有 Face ID | 仅识别，不加入图库或 pending |
| `[0.43,0.5)`，支持不足 | 待确认，`face_id=0/faceStatus=0` | 不新建、不入库 |
| 图库为空或最高分 `<0.43` | 正常未命中 | 仅 2 级可创建 Face ID 并提交向量 |
| 检索异常 | 未分配 | 不新建、不入库 |

下限来自 `face.matching.general_similarity_threshold=0.43`，单样本确认线来自 `face.matching.single_sample_similarity_threshold=0.5`（均见 `config/algorithm.toml`）。独立人脸与人型 crop 内绑定共用该规则，crop 内绑定仅查询/复用已有 Face ID。

灰区支持按 `sampleId` 或 `faceCropPath` 去重，任一标识相同只计一次；两类标识都缺失的记录不提供支持。Milvus 和 pending 各有一条不同样本可以共同确认，且每条分数都必须达到下限。证据不足时不改选低分身份，保留最高分及候选 ID 供诊断；不设置跨 ID 分差门槛，也不建立跨帧候选缓存。

### 2. 人脸 ID 与入库规则

| 等级 | 是否查询向量库 | 命中已有 ID | 未命中已有 ID | 是否写入向量库 |
| --- | --- | --- | --- | --- |
| `0级` | 否 | 不处理 | 不生成新 ID | 否 |
| `1级` | 是 | 分配已有 `face_id` | 不生成新 ID | 否 |
| `2级` | 是 | 复用已有 `face_id` | 正常未命中生成新 ID；灰区不足保持 `0` | 新生或最高分 `>=0.5` 的已有 ID 可写入；灰区不写入 |

人型 crop 内绑定不创建 Face ID；独立人脸的新生识别记录等待首次向量持久化确认。

### 3. 人型 ReID 与入库规则

| 等级/人脸 | 查询结果 | ReID行为 | 生命周期 | SBS行为 |
| --- | --- | --- | --- | --- |
| `0级` | 不查询 | `reid=0` | 空 | 不写 |
| `1级` | 命中 ACTIVE | 复用已有 `reid` | `ACTIVE` | 不更新 |
| `1级` | 未命中 | `reid=0` | 空 | 不写 |
| `2级`、当前有脸 | 命中/未命中 | 复用同脸外观簇，或创建新 `reid` | 当前人脸确认后为 `ACTIVE` | 提交正式原型更新检查 |
| `2级`、匿名 | 命中 ACTIVE | 复用已有 `reid` | `ACTIVE` | 不调用 enrollment，状态/原因为空 |
| `2级`、匿名 | 未命中 | `reid=0/UNASSIGNED` | 空 | 不创建、不扩充 SBS |

SBS enrollment 使用当前观察人脸，不能用继承的 `canonicalFaceId` 代替。2 级仅授予提交资格，最终更新取决于重复、离群、身份冲突和原型容量策略；新生识别记录等待正式 SBS 持久化确认。匿名流程跳过 enrollment，状态与原因为空；直接调用 SBS buffer 提交匿名样本时返回 `REJECTED/face_required`。

TBPS 独立判断：最终 2 级且 CLIP 特征有效即可写入，即使 `faceId/reId` 均为 `0`。SBS 查询矩阵、同帧互斥、类级解析和原型策略统一见[人型 ReID 识别完整流程](人型ReID识别完整流程.md)。
